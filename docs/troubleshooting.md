# Troubleshooting Guide

`mswap doctor` checks your installation, credential vault, storage permissions, and network connectivity.

Run diagnostics anytime:
```powershell
mswap doctor
```

To include network checks (token refresh and quota endpoints):
```powershell
mswap doctor --online
```

To automatically repair recoverable issues:
```powershell
mswap doctor --repair
```

---

## Diagnostics by Check ID

### agy.installed
- **Symptom**: `✗ agy not found at ...`
- **Cause**: Antigravity CLI executable is not found at `%LOCALAPPDATA%\agy\bin\agy.exe`.
- **Fix**: Install `agy`, or set the `MSWAP_AGY_EXE` environment variable to point to your `agy.exe` path:
  ```powershell
  $env:MSWAP_AGY_EXE = "C:\Path\To\agy.exe"
  ```

### agy.login
- **Symptom**: `! agy is signed out` or `✗ agy's login entry is damaged`
- **Cause**: Windows Credential Manager does not contain `gemini:antigravity`, or the stored blob cannot be parsed as valid JSON.
- **Fix**: Open `agy` and complete the standard sign-in prompt:
  ```powershell
  agy
  ```

### agy.client
- **Symptom**: `✗ agy OAuth client credentials not found in ...`
- **Cause**: `mswap` could not locate or extract OAuth client credentials from `agy.exe` or cache.
- **Fix**: Run `agy` once to verify it is working, then run:
  ```powershell
  mswap doctor --repair
  ```

### agy.sessions
- **Symptom**: `! N stale session credential file(s) found in ...`
- **Cause**: Prior sessions left temporary credential files after an abrupt process termination.
- **Fix**: Clean up leftover session files automatically:
  ```powershell
  mswap doctor --repair
  ```

### store.readable
- **Symptom**: `✗ store file damaged or unreadable`
- **Cause**: `accounts.json` contains invalid JSON or schema errors.
- **Fix**: Check `%LOCALAPPDATA%\mswap\accounts.json`. If unrecoverable, remove it and re-add your accounts with `mswap add`.

### store.slots
- **Symptom**: `! slot N (user@example.com) credential missing in vault`
- **Cause**: An account exists in `accounts.json`, but its credential target `mswap:slotN` was deleted from Windows Credential Manager.
- **Fix**: Sign in to that account in `agy`, then run:
  ```powershell
  mswap add
  ```

### store.orphans
- **Symptom**: `! N orphan credential(s) in vault not tracked in store`
- **Cause**: Vault targets exist (such as old slot credentials) that are no longer listed in `accounts.json`.
- **Fix**: Automatically prune orphaned credentials:
  ```powershell
  mswap doctor --repair
  ```

### store.active
- **Symptom**: `! agy is logged into an account not tracked by mswap`
- **Cause**: You logged into a new account directly in `agy`, but have not added it to `mswap`.
- **Fix**: Save the new account to `mswap`:
  ```powershell
  mswap add
  ```

### journal
- **Symptom**: `! interrupted switch transaction detected`
- **Cause**: A previous switch was interrupted mid-flight (power loss, terminal crash).
- **Fix**: Automatically roll back and commit the journal:
  ```powershell
  mswap doctor --repair
  ```

### data.writable
- **Symptom**: `✗ data directory is not writable`
- **Cause**: Permissions on `%LOCALAPPDATA%\mswap` prevent creating or editing files.
- **Fix**: Verify file system permissions for your Windows user account on `%LOCALAPPDATA%\mswap`.

### win.launchers
- **Symptom**: `! Smart App Control or Defender may block unsigned launchers`
- **Cause**: Windows Smart App Control (SAC) blocks unsigned `.exe` entrypoints generated by Python package installers.
- **Fix**: Run via `python -m mswap`:
  ```powershell
  uv run python -m mswap list
  ```

### net.refresh
- **Symptom**: `✗ token refresh failed for slot N`
- **Cause**: Google OAuth refresh token was revoked or expired (`invalid_grant`), or no network connectivity is available.
- **Fix**: Sign in as that account in `agy` again, then run:
  ```powershell
  mswap add
  ```

### net.quota
- **Symptom**: `✗ quota API check failed (HTTP ...)`
- **Cause**: Network failure or upstream Google Cloud Code Assist endpoint error.
- **Fix**: Check your internet connection. If the endpoint is rate-limited, wait 60 seconds and retry:
  ```powershell
  mswap doctor --online
  ```

## Automatic Repair

`mswap doctor --repair` safely fixes common operational issues without data loss:

1. **Interrupted switches**: Resolves uncommitted journals by checking the live target against the target fingerprint and restoring the previous state if incomplete.
2. **Orphaned vault targets**: Deletes untracked `mswap:slot*` vault entries that no longer correspond to accounts in `accounts.json`.
3. **Stale temporary session files**: Cleans up abandoned session directories in `%LOCALAPPDATA%\mswap\sessions`.
